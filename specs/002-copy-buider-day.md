# Spec 002: Копирование плана дня в другую дату

Связана со Spec 001. Эта спека — клиент текущего экрана тренера. Сохранение вставленного черновика остаётся пунктом «Сохранить» и `POST /api/saveBuilderDay`. Тело сохранения — `{ date, athleteId, workoutName, plan }` (Delta 005). Мок Spec 003 не меняется этим копированием: отдельного запроса на копирование нет.

## User Story
Как тренер, я хочу скопировать содержание выбранной даты в `BuilderDay` и вставить этот план в другую дату, чтобы не набирать те же блоки заново. Вставленный план остаётся черновиком новой даты, пока я его не сохраню.

## Как устроен текущий экран
Менять каркас экрана не нужно.

- Дата уже лежит в сторе. `BuilderDay` читает её через `selectCurrentDate`. Смена даты — тот же календарь.
- Пункты «Копировать» и «Вставить» уже есть в `widgets/builder-day/ui/BuilderDay.tsx`. Отдельные кнопки не добавляются.
- Черновик пары спортсмен + дата — локальный `DayDraft`: `workoutName`, `activeKeys`, `texts`. Его по-прежнему заполняет Spec 001. Копируется этот черновик, а не новый ответ сервера.
- Буфер один на сессию конструктора и не привязан к дате. Смена `selectCurrentDate` его не очищает.
- «Редактировать» и «Сохранить» остаются как в Spec 001.
- `GrowingTextArea` остаётся локальной функцией в `BuilderDay.tsx`.

## Acceptance Criteria
1. Пункт «Копировать» доступен, когда у выбранной даты уже есть черновик: его заполнил ответ `GET` или тренер уже менял эту дату. Пока запрос даты без черновика не завершился, пункт заблокирован. Пустая форма на время запроса в буфер не попадает.
2. Нажатие «Копировать» кладёт в буфер копию черновика выбранной даты: `workoutName`, `activeKeys` и `texts`. Пустая строка названия и пустая строка блока копируются. В буфере только известные ключи `PlanSectionKey`, которые уже есть в черновике. Порядок ключей черновика сохраняется.
3. После копирования правка исходной даты буфер не меняет. Повторное «Копировать» заменяет буфер целиком.
4. Пункт «Вставить» заблокирован, пока буфер пуст. После успешного «Копировать» пункт доступен на любой дате, включая исходную.
5. Нажатие «Вставить» заменяет черновик выбранной даты копией буфера. Поля не сливаются со старым черновиком этой даты. Дата, с которой копировали, не меняется. Буфер после вставки остаётся: ту же копию можно вставить в следующую дату.
6. Вставленный черновик считается правкой тренера. Следующий ответ `GET` на эту дату его не затирает. Повторный заход на эту дату в той же сессии показывает вставленный черновик.
7. «Вставить» не шлёт `POST` и не инвалидирует `DayPlan`. Дата переходит в режим редактирования, если ещё не была в нём. Меню закрывается. Сохранение вставленного плана — тот же пункт «Сохранить» из Spec 001: тело `{ date, athleteId, workoutName, plan }` собирается уже из черновика новой даты.
8. Смена роли на спортсмена показывает в `DayView` вставленный план только после «Сохранить» на эту дату. До сохранения карточка дня остаётся прежней.

## FSD Placement
Новая фича, новый эндпоинт и второй `createApi` не заводятся. Буфер и оба пункта остаются в виджете.

- `widgets/builder-day/ui/BuilderDay.tsx` — «Копировать» снимает копию `DayDraft` выбранной даты, «Вставить» записывает эту копию в черновик текущей `selectCurrentDate` и включает режим редактирования. Виджет по-прежнему вызывает `useDayPlanQuery` из `features/select-day` только для начального черновика Spec 001.

## Out of Scope
- Новый экран, новые кнопки и перенос `GrowingTextArea`.
- Запрос копирования на сервер. Мок Spec 003 не меняется.
- Автосохранение после вставки. Пока тренер не нажал «Сохранить», `GET /api/dayPlan` новой даты отдаёт прежнюю запись.
- Слияние блоков вставленного плана с уже набранным черновиком даты.
- Отдельный запрос копирования между спортсменами. Буфер хранит содержание черновика, без `athleteId`. «Вставить» пишет в черновик текущей пары. После «Сохранить» план принадлежит этой паре.
- Системный буфер обмена браузера.

## Тесты
- `widgets/builder-day/ui/BuilderDay.test.tsx`:
  - «Копировать» на дате с черновиком запоминает `workoutName`, активные блоки и их текст, включая пустую строку;
  - пока запрос даты без черновика не завершился, «Копировать» заблокирован;
  - после смены `selectCurrentDate` «Вставить» заменяет черновик новой даты этой копией и не оставляет её прежних блоков;
  - черновик исходной даты после вставки тот же;
  - правка исходной даты после копирования не меняет то, что вставляется;
  - без копирования «Вставить» заблокирован;
  - вставка не вызывает `POST /api/saveBuilderDay`; дата в режиме редактирования, и тот же черновик уходит в сохранение Spec 001.
