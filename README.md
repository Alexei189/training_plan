# Training Plan

**Fullstack-приложение для планирования тренировок** (React 18 + TypeScript + Express) с выстроенным процессом **AI-ассистированной разработки** (Harness, SDD, TDD, управление контекстом).

> ⚠️ **Статус:** Функционал реализован на ~20%. Проект используется как полигон для отработки современного инженерного процесса с AI-агентом (Cursor). Архитектура (FSD) и процесс (Harness + Specs) уже заложены.

---

## 🛠️ Engineering Process

Этот проект — не просто CRUD-приложение. Это демонстрация того, как выстроить управляемую разработку с AI-агентом, чтобы генерируемый код соответствовал строгой архитектуре и верифицировался.

### 1. Harness (Слой постоянных инструкций агента)
Создан файл [`AGENTS.md`](./AGENTS.md), который Cursor автоматически читает перед генерацией кода. В нём зафиксированы:
- Архитектура **Feature-Sliced Design (FSD)** и правила импортов между слоями.
- Паттерны работы с **RTK Query** (регистрация эндпоинтов, теги).
- Правила маршрутизации по ролям (`athlete` / `coach`).
- Команды запуска и проверки (`typecheck`, `test:run`).

*Результат:* AI-агент не нарушает границы слоёв FSD и следует конвенциям проекта.

### 2. Spec-Driven Development (SDD)
Каждая новая фича начинается с файла спецификации в папке [`specs/`](./specs/). Спецификация описывает **что** нужно сделать (пользовательские истории, критерии приёмки) и **где** это должно жить в FSD.

- Пример: [`specs/001-save-coach-day-plan.md`](./specs/001-save-coach-day-plan.md) — сохранение плана тренировочного дня тренером.
- Процесс: спецификация → план изменений (Plan Mode в Cursor) → реализация → проверка.

*Результат:* Контракт между разработчиком и AI явный, снижается количество возвратов на доработку.

### 3. TDD (Test-Driven Development)
Критическая логика разрабатывается через цикл RED-GREEN-REFACTOR. Тесты пишутся **до** кода.

- Пример: [`src/features/select-day/model/useDayPlanQuery.test.tsx`](./src/features/select-day/model/useDayPlanQuery.test.tsx).
- Для новых фич: сначала падающий тест, затем реализация через Cursor, затем рефакторинг.

*Результат:* AI-генерируемый код верифицируется тестами, а не доверием.

### 4. Управление контекстом (элементы GSD)
Используется фазовое планирование для борьбы с «context rot» (деградацией контекста в длинных сессиях).

- Файл [`ROADMAP.md`](./ROADMAP.md) разбивает оставшийся функционал на фазы (A, B, C).
- Перед началом новой фазы контекст агента «сбрасывается» перечитыванием Harness и Roadmap.

*Результат:* Длительная разработка остаётся предсказуемой, агент не «забывает» архитектурные решения.

### 4. Артефакты процесса 
журнал инженерных решений в рамках работы над проектом. Отражаются Spec и Delta Spec, чтобы была видна история изменений, затрагивающих несколько фич
- Файл [`JOURNAL.md`](./JOURNAL.md)
