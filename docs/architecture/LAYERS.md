# FSD: слои, сегменты, экспорты

Load when: добавляешь слайс, переносишь код между слоями, сомневаешься в направлении импорта.

Код приложения лежит в `src/`. Алиас `@/*` → `src/*`. Новый код повторяет эти схемы.

## Слои

Зависимости идут только вниз:

`app` → `pages` → `widgets` → `features` → `entities` → `shared`

Слайс берёт код только из слоёв ниже. Соседний слайс того же слоя не импортируется. Общее для двух соседей выносится в `shared` или в слой ниже.

| Слой | Что здесь живёт |
|---|---|
| `app` | Стор, провайдеры, роутер, каркас экрана. Образец стора: `src/app/store`. |
| `pages` | Сборка одного маршрута из виджетов. Образец: `src/pages/plan`. |
| `widgets` | Самостоятельный блок экрана. |
| `features` | Одно действие пользователя: слайс, селекторы, хук сценария. |
| `entities` | Домен: типы и серверное состояние. |
| `shared` | `api`, `config`, `lib`, `ui` без знания домена. |

## Сегменты

У слайса сегменты по необходимости: `ui/`, `model/`, `api/`. Пустой сегмент не заводится.

## Экспорты

Снаружи слайс виден только через свой `index.ts`. Импорт из внутреннего файла (`@/entities/day-plan/model/...`, `@/features/select-day/model/...`) не используется. Нужный хук, слайс, селектор или тип реэкспортируется из `index.ts` и импортируется оттуда: `@/entities/day-plan`.

- Страница и виджет: компонент объявлен через `export default` в `ui/`, из `index.ts` выходит именованный реэкспорт. Образцы: `src/pages/plan/index.ts`, `src/widgets/builder-day/index.ts`.
- Хук, слайс, селектор и тип — именованный экспорт и из модуля, и из `index.ts`.

Публичный вход фичи — именованный хук или селектор из её `index.ts`. Фича не импортирует соседнюю фичу. Дату, спортсмена и тело запроса собирает виджет и передаёт в хук.
